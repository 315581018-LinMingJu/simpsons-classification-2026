# 使用者給 AI 的操作偏好

> 來源：使用者在對話中陸續提出的要求，由 Claude 整理成 Claude Project 文件，之後每次接手都依此執行。

## 長時間工作必須「看得到」
- 不要讓工作在看不到的背景執行（例如 `tmux new-session -d` 直接丟到背景）。
- 長時間訓練／推論：先 `tmux new -s <名稱>` 或 `tmux attach -t <名稱>` 進入 tmux，再在**前景**貼上指令，讓進度條直接顯示在畫面上；需要離開時由使用者自己按 Ctrl+B → D。
- 同時跑兩個工作時：先徵求同意，再用一個終端機、tmux 左右分割畫面（Ctrl+B 再按 %），兩個進度條同時看得到。

## 其他偏好（詳見 `01_handoff_prompt_V1-V17.md`、`02_github_rules.md`）
- 指令分步驟給，每步標示：用途、是否需要 tmux、是否需要 GPU、預估時間、完成後應看到什麼。
- 回傳只貼 `===== 請貼這段開始 =====` 與 `===== 請貼這段結束 =====` 之間的內容。
- 進度條須顯示：已完成張數／總張數、百分比、經過時間、ETA，依實際完成的 batch 更新。
- 正式提交檔命名 `submission_vN.csv`；AI 不替使用者提交 Kaggle。
- 遇到需要決定的事（多 GPU、推 main、規則解讀）先問使用者。
- 全程繁體中文。
