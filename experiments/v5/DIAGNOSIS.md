# V5 結果稽核與困難驗證

## 舊 V5 驗證的限制

舊版在同一批原圖上切換 `stress`，依相同 ID 固定紋理種子，且逐批推論前處理沿用 V3 Multi-scale。檢查原始碼和 CPU 重播後，未發現把 `heldout_background` 指到 Clean 輸入的錯誤。外圍遮罩仍會漏掉部分黑邊，也可能碰到與邊界相連的暗部，因此只能視為保守的外框近似。

在附件的 200 張訓練圖上，196 張有可替換外框，遮罩比例中位數 34.25%。用 Pillow 模擬這些方圖的 `Resize(256) → CenterCrop(224)`，比較舊驗證紋理加入前後，跨圖片的中位數為 23.66% 像素至少一個 RGB 通道改變超過 5 階。只有 6 張在這個中心視角沒有可見改變。這是附件上的 CPU 檢查，並未使用 Server 的實際驗證圖或測量所有十個視角。

舊 Heldout 主要替換外框，保留動畫圖塊的視角、大小、內容、色彩。V2 在該條件仍達 99.6667%，可能因為仍有充足的角色線索。兩組同為 +0.1667 pp 無法證明是同一批救回或退步，區間跨 0 也不足以支持提升。先讀逐圖紀錄，分辨預測完全相同、錯誤 ID 對調、或錯到另一個類別。

## 真實圖片提供的方向

使用附件的 200 張訓練圖、100 張隨機測試圖與 67 張特選改判圖。照片背景可與動畫區塊分辨，常見木材、磚牆、室內或街景。隨機組可以看到小區塊（6949）、貼近邊緣的裁切（810、6392）、旋轉與透視（3186、9736）、兩個以上可見角色（7812）與看似整塊反色（6042、5830）。改判組的重雜訊、變形及灰階可用來找失敗機制，不能當作全體出現率。ID 提供的是可見影像案例，沒有假定比賽要求辨識其中哪一個角色。

較接近測試的標記驗證應在相同已知標籤圖片上，逐步加入小圖塊、偏移、旋轉／透視、背景、裁切與另一角色。照片背景難以用少量紋理完全重現。優先用不含任何競賽測試像素的程序背景量化機制，之後如確認背景效應大，再考慮合法且與比賽無關的照片素材做確認。避免從測試圖切背景帶入角色線索。

## 驗證設計

沿用原 V5 去重驗證清單，每類最多 12 張，固定種子。原 Train 只提供異類小圖塊。兩台模型的推論前處理和 Multi-scale 完全相同。條件間用相同圖片比較：

| 條件 | 對照條件 | 改動 |
| --- | --- | --- |
| Clean | — | 原始驗證圖 |
| Geometry | Clean | 以 V5 外框遮罩取出來源圖塊，放到 264×264 黑底。長邊占畫布約 40–70%，偏向四角，旋轉 ±12–30° 並加入透視 |
| Context | Geometry | 保留完全相同的圖塊與位置，將黑底替換成程序紋理 |
| Clipped | Context | 僅裁來源圖塊一側的 10–17% 寬度或高度 |
| Distractor | Context | 在對角空位放一張更小、不同類的 Train 圖塊 |
| Negative | Context | 僅反色來源圖塊，保留原背景與位置 |

在附件 200 張訓練圖上，Geometry 的來源圖塊 alpha 面積中位數 13.44%；Clipped 保留原圖塊面積的中位數為 89.03%；Distractor 的次要圖塊中位數占畫布 3.02%。這是渲染後的圖塊面積，與人工角色框不同。裁切仍可能移除重要線索。合成多角色以主要來源圖塊為答案，比賽真實多角色的標註規則可能不同。

報告用相同圖的父子條件差衡量 V2、V5 的下降，也報告 V5 相對 V2 的救回、退步、共同錯誤、類別等權的配對 95% bootstrap 區間。錯誤少於 5% 的條件會標示 `near_ceiling`。小圖塊以 Geometry alpha 面積 12% 為切片界線，同一圖在所有條件都屬於同一大小組。區間用於探索性診斷，不能估計 Kaggle 分數。

截止前先找一個顯著而可解釋的落差，避免重訓。若 V2、V5 對 Negative 都大幅下降，而盲看真實圖也能辨認反色，優先驗證原圖與反轉視角的低成本推論；須同時看非反色圖是否出現新錯誤。若額外損失主要出在 Context 或 Geometry，優先在既有權重上比較保留視野或區塊定位。只有 V5 在較難的配對條件有可重複收益、Clean 沒有實質退步時，才把 V5 當候選。若所有條件仍近天花板，下一步是少量獨立合法標註的真實風格圖，避免反覆加大合成強度。

## 執行與產物


`audit` 只讀 V5 的 `paired_predictions.csv` 和可用的 `validation_samples.csv`，將配對摘要印到標準輸出。若只有時間執行一項，先回傳這段 JSON，可知道救回／退步的類別和 ID，以及模型在 Clean、Heldout 是否錯在同一批圖。

```bash
nvidia-smi
read -r -p "已確認可使用的一張 GPU index：" gpu_index
CUDA_VISIBLE_DEVICES="$gpu_index" .venv/bin/python -u diagnose_v5.py challenge
```

預設單 GPU、batch size 16、workers 2、約 600 張×6 條件×2 權重×10 視角。粗估 RTX 5090 需 **5–20 分鐘、2–6 GiB VRAM**，尚未實測。輸出 `runs/v5_challenge/` 包含 `challenge.json`、`paired_predictions.csv`、`sample_manifest.csv`、`challenge_examples.png` 和 `preview_geometry.json`。預覽在推論前先寫出。若需重跑，使用新的 `--output runs/v5_challenge_...`。V1～V5 原資料與跑次僅讀取，不會訓練或產生 Submission。

只需回傳 `audit` 的 JSON 與 `runs/v5_challenge/challenge.json`。單圖圖片和權重均可留在 Server。
